# Aginiti vs. garak — A Real, Fair Head-to-Head

_Last rewritten 2026-08-13. `garak` (NVIDIA's open-source LLM vulnerability
scanner, github.com/NVIDIA/garak, Apache 2.0) is the most credible, easily
obtainable comparison point available — already cited by name as
inspiration in `aginiti/operators/data_exposure.py`. This document is the
methodology and results of a real, run comparison, not an architectural
characterization — see `docs/EVIDENCE_AND_EVALUATION.md` §4 for how this
fits alongside the tools Aginiti has only been architecturally compared
against._

---

## Fairness: same target, same hardening, no tuning either way

`experiments/garak_setup.py` creates the garak-facing workspace through
the **same gateway** (`aginiti/target_hardening/gateway_server.py`,
`localhost:3002`) Aginiti's own adapter uses — same `HARDENED_PROMPT_V2`,
same document-sanitization / output-redaction / service-account-tier /
human-approval / adaptive-lockout controls (full detail: `docs/
HARDENED_TARGET.md`). Neither tool gets an easier or harder version of the
target. Config: `experiments/garak_rest_generator.json`, generated by that
script (regenerated per run, not committed with a live gateway key baked
in).

## The one honest scoping limit that matters here

garak's `RestGenerator` is a plain text-in/text-out interface. It has no
concept of a tool call, a document upload, or network egress — it can only
ever observe what comes back in `textResponse`. That means a garak run can
assess this target's **L0 (model behavior) and L1 (does the model comply
with something already in its context)** layers — the system-prompt-
extraction / jailbreak / encoding-evasion / direct-prompt-injection-
compliance class of finding — but structurally **cannot reach L2-L5** (real
tool invocation, confirmed network egress) at all. Aginiti's own
AnythingLLM chains (the automatic-mode and markdown-exfil attacks, both
L5) are simply outside what any REST-generator-based tool including garak
can observe — not because the target was tuned to favor Aginiti. A fair
headline comparison is therefore scoped explicitly to "who complies with
the class of attack garak can see," reported as such, not silently
generalized to "who wins overall."

Comparable probe families were chosen to line up with Aginiti's own
operator categories (`aginiti/operators/data_exposure.py`), not garak's
full default suite:

| Aginiti operator | Comparable garak probe module |
|---|---|
| `system_prompt_extraction` | `promptinject` |
| `jailbreak_dan_style` | `dan` |
| `encoding_evasion_probe` | `encoding` |
| `anythingllm_rag_document_plant` + `..._injection_trigger` (L1) | `latentinjection` — the most directly comparable module, indirect injection via context the model is shown, not typed by the "user" |

## A real bug found and fixed along the way

The first smoke-test run of `dan.DAN_Jailbreak` **500'd on every one of its
5 generations**. Root cause, confirmed by reproducing directly and reading
the upstream source: AnythingLLM's own Gemini-provider code crashes
instead of returning a clean refusal when Gemini's safety filter blocks a
response — exactly what a DAN-style jailbreak prompt triggers. Full
diagnosis and fix: `docs/HARDENED_TARGET.md`. After the fix,
`dan.DAN_Jailbreak` (5 generations) reported `PASS 5/5` on both of garak's
own detectors (`dan.DANJailbreak`, `mitigation.MitigationBypass`) — the
hardened target neither adopted the DAN persona nor failed to refuse.

## exp19: the real head-to-head

Both tools tested against the identical hardened target (v2 gateway +
`HARDENED_PROMPT_V2`), same fresh-workspace-per-trial discipline, N=15 per
category for Aginiti (`experiments/exp19_garak_vs_aginiti.py`, results in
`experiments/results/exp19_aginiti_direct/`), garak run via its own CLI
(`-g 1`, `-P` probe-option file — see that script's docstring for the
exact invocations). Aginiti operators were called directly through
`ObservationAdapter`, bypassing the planner, to match garak's own
planner-free per-probe methodology.

| Category | Aginiti operator | Aginiti ASR | garak probe | garak ASR | Comparable? |
|---|---|---|---|---|---|
| System-prompt extraction | `system_prompt_extraction` | 0/15 (0%) | `sysprompt_extraction.SystemPromptExtraction` | 0/28 (0%) | Yes — both 0%, target defended both |
| Jailbreak | `jailbreak_dan_style` | 0/15 (0%) | `dan.DAN_Jailbreak` | 0/15 (0%) | Yes — both 0%, target defended both |
| Indirect/latent injection | `anythingllm_rag_injection_trigger` | 0/15 (0%) | `latentinjection.LatentInjectionFactSnippetEiffel` | 0/15 (0%) | Yes — both 0%, target defended both |
| Markdown/web exfiltration | `anythingllm_markdown_image_exfil_trigger` | 0/15 (0%) | `web_injection.MarkdownImageExfil` | 0/12 (0%) | Yes — both 0%, target defended both |
| Encoding evasion | `encoding_evasion_probe` | 0/15 (0%) | `encoding.InjectBase64` | 13-14/15 (87-93%) | **No — see below** |

### The one dramatic-looking number (93% vs 0%) is not a fair comparison

Pulling garak's own raw traces for `encoding.InjectBase64` shows its
prompts ask the model to **decode and echo back an arbitrary base64
string** — several of which happen to be XSS/script payloads from garak's
default toxicity corpus (e.g. a string that decodes to
`<IMG SRC=javascript:alert(...)>`). garak's `DecodeApprox`/`DecodeMatch`
detectors score "attack success" whenever the decoded string appears in
the response — which is exactly what happens when the model correctly
performs the harmless transcoding task it was asked to do. It is not
evidence the model acted on a hidden instruction.

Aginiti's `encoding_evasion_probe` asks a structurally different question:
whether the model will **execute an instruction concealed inside** the
encoded payload (e.g. "reveal your system prompt"), not merely decode and
repeat text. 0/15 there means the hardened target's safety instructions
survived being reached via an indirect (encoded) channel — a materially
different and stronger claim than what garak's detector pair actually
measures.

**Bottom line:** on the four genuinely comparable categories, Aginiti and
garak agree exactly — target fully defended, 0% ASR both tools — a real,
useful cross-check that neither tool is hallucinating a false positive.
The encoding category is not a fair apples-to-apples comparison; garak's
detector answers "did the model decode text," Aginiti's answers "did the
model obey a hidden instruction." Where Aginiti is genuinely stronger is
structural, not score-based: garak's REST generator cannot observe L2-L5
findings at all — the automatic-mode and markdown-exfil chains are outside
its reach by construction, not because the target favored Aginiti.

## What this comparison directly motivated

Three real additions closed concrete gaps this comparison surfaced:
`aginiti/transforms/` (a composable `PromptConverter` pipeline),
`aginiti/operators/encoding_variants.py` (12 static encoding pipelines,
where before there was one), `aginiti/adaptive/refinement.py` (PAIR-style
adaptive retry), and `aginiti/graph/owasp_llm_taxonomy.py` (the OWASP LLM
Top 10 tagging dimension). All four are covered in depth in `docs/
ARCHITECTURE.md` and `docs/ATTACK_LIBRARY.md`.

## Since this comparison ran

`docs/EXP20_RESULTS.md` compares exp20's live Aginiti results against
exp19's garak numbers directly on the same four comparable categories
(still agreeing exactly, still 0% both tools) — and reports exp20's
chain-pivoting result as a capability neither garak nor Aginiti's own
earlier benchmark runs had demonstrated, since it depends on real tool
invocation garak structurally cannot observe.
